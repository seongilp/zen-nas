# zen NAS OS 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 맥북(M4 Pro)에서 FreeBSD VM으로 NanoBSD amd64 이미지를 크로스 빌드하고 USB에 구워 x86-64 홈 NAS로 부팅하는 전체 파이프라인 구축.

**Architecture:** macOS는 조종석 역할만 한다(설치물은 Homebrew의 qemu·shellcheck뿐). QEMU aarch64 VM(FreeBSD, HVF 네이티브 가상화) 안에서 `nanobsd.sh`로 amd64 이미지를 크로스 빌드하고, scp로 회수해 QEMU x86-64로 스모크 테스트 후 `dd`로 USB에 굽는다. OS는 읽기전용 UFS(듀얼 슬라이스 A/B + `/cfg`), 데이터는 별도 디스크의 ZFS 풀.

**Tech Stack:** FreeBSD 14.x-RELEASE, NanoBSD(`tools/tools/nanobsd`), QEMU(HVF/TCG), qemu-user-static(binmiscctl 크로스 chroot), pkg(Samba·rsync·lighttpd), bash/sh 스크립트.

**참고 스펙:** `docs/superpowers/specs/2026-07-10-zen-nas-os-design.md`

## 전제 지식 (실행자 필독)

- **NanoBSD**는 FreeBSD 소스 트리 안의 셸 스크립트 프레임워크(`/usr/src/tools/tools/nanobsd/nanobsd.sh`)다. `.conf` 파일 하나를 받아 `buildworld` → `buildkernel` → 이미지 조립까지 수행한다. **FreeBSD 위에서만 실행 가능**하므로 VM이 필수다.
- **크로스 빌드**: FreeBSD는 aarch64 호스트에서 `TARGET_ARCH=amd64` 빌드를 공식 지원한다. 이미지에 **패키지를 설치하는 단계**는 NanoBSD 기본(`cust_pkgng`, amd64 chroot에서 pkg 실행)을 쓸 수 없다 — `emulators/qemu-user-static` 포트가 `ONLY_FOR_ARCHS: amd64 powerpc*`라서 aarch64 호스트용 에뮬레이터 패키지가 존재하지 않는다(Task 5 실행 중 확인). 대신 **호스트(aarch64) 네이티브 pkg가 `--rootdir` + `-o ABI=FreeBSD:15:amd64`로 amd64 패키지를 이미지 루트에 직접 설치**한다(설치 스크립트는 amd64 바이너리라 실행 불가 → 스크립트 생략 옵션 사용, 스크립트가 하던 일 중 필요한 것은 오버레이로 보상). 이 기법은 Task 5에서 소형 패키지로 선검증한다.
- **NanoBSD 산출물**: `${NANO_OBJ}/_.disk.full`(전체 미디어 이미지 — USB에 굽는 것), `_.disk.image`(슬라이스 하나 — 가동 중 업데이트용). 기본 `NANO_OBJ`는 `/usr/obj/nanobsd.${NANO_NAME}`.
- **버전 정책**: 이 계획은 FreeBSD **14.3-RELEASE**를 기준으로 작성했다. Task 3 Step 1에서 최신 RELEASE를 확인해 더 새 버전이 있으면 `FREEBSD_VER`만 바꾸면 된다(스크립트가 전부 변수화되어 있다).
- 맥 쪽 스크립트는 bash, VM 안에서 도는 스크립트는 POSIX sh(#!/bin/sh)로 작성한다.

### Task 2: flash-usb.sh — 안전장치 있는 USB 플래셔

VM 없이도 개발·검증 가능한 부분이라 먼저 만든다. **핵심은 내장 디스크 오폭 방지.**

**Files:**
- Create: `scripts/flash-usb.sh`

- [ ] **Step 1: 스크립트 작성**

```bash
#!/usr/bin/env bash
# zen 이미지를 USB에 굽는다. 외장·이동식 디스크만 허용한다.
set -euo pipefail

IMG="${1:-build/zen.img}"
if [[ ! -f "$IMG" ]]; then
    echo "오류: 이미지 파일이 없습니다: $IMG" >&2
    echo "사용법: $0 [이미지경로]" >&2
    exit 1
fi

echo "== 연결된 외장 물리 디스크 =="
diskutil list external physical
echo

read -r -p "구울 대상 디스크 식별자 (예: disk4): " DISK
if [[ ! "$DISK" =~ ^disk[0-9]+$ ]]; then
    echo "오류: 'diskN' 형식이어야 합니다: $DISK" >&2
    exit 1
fi

# 안전장치 1: 내장 디스크 거부
INTERNAL=$(diskutil info -plist "$DISK" | plutil -extract Internal raw -)
if [[ "$INTERNAL" != "false" ]]; then
    echo "오류: $DISK 는 내장 디스크입니다. 중단합니다." >&2
    exit 1
fi

# 안전장치 2: 대상 정보를 보여주고 명시적 확인
diskutil info "$DISK" | grep -E "Device Node|Media Name|Disk Size"
echo
read -r -p "위 디스크의 모든 데이터가 삭제됩니다. 계속하려면 ERASE 입력: " CONFIRM
if [[ "$CONFIRM" != "ERASE" ]]; then
    echo "취소했습니다."
    exit 0
fi

diskutil unmountDisk "/dev/$DISK"
echo "== 굽는 중: $IMG → /dev/r$DISK =="
sudo dd if="$IMG" of="/dev/r$DISK" bs=4m status=progress
sync
diskutil eject "/dev/$DISK"
echo "완료. USB를 NAS에 꽂고 부팅하세요."
```

```bash
#!/usr/bin/env bash
# FreeBSD aarch64 빌드 VM 디스크를 다운로드·준비한다 (최초 1회).
set -euo pipefail

FREEBSD_VER="${FREEBSD_VER:-14.3}"
VM_DIR="vm"
DISK="$VM_DIR/builder.qcow2"
URL="https://download.freebsd.org/releases/VM-IMAGES/${FREEBSD_VER}-RELEASE/aarch64/Latest/FreeBSD-${FREEBSD_VER}-RELEASE-arm64-aarch64.qcow2.xz"

if ! command -v qemu-system-aarch64 >/dev/null; then
    echo "오류: qemu가 없습니다. brew install qemu 를 먼저 실행하세요." >&2
    exit 1
fi

if [[ -f "$DISK" ]]; then
    echo "이미 존재합니다: $DISK (다시 만들려면 삭제 후 재실행)"
    exit 0
fi

mkdir -p "$VM_DIR"
echo "== 다운로드: $URL =="
curl -fL --progress-bar -o "$DISK.xz" "$URL"
echo "== 압축 해제 =="
xz -d "$DISK.xz"
echo "== 디스크 80G로 확장 (FreeBSD가 첫 부팅 때 자동 growfs) =="
qemu-img resize "$DISK" 80G
echo "완료. scripts/vm-run.sh 로 부팅한 뒤 docs/vm-bootstrap.md 절차를 따르세요."
```

- [ ] **Step 3: vm-run.sh 작성**

```bash
#!/usr/bin/env bash
# 빌드 VM을 기동한다. 콘솔은 이 터미널에 붙는다 (종료: VM 안에서 poweroff).
set -euo pipefail

DISK="vm/builder.qcow2"
FW="$(brew --prefix)/share/qemu/edk2-aarch64-code.fd"
CPUS="${ZEN_VM_CPUS:-8}"
MEM="${ZEN_VM_MEM:-16384}"

if [[ ! -f "$DISK" ]]; then
    echo "오류: $DISK 가 없습니다. scripts/vm-setup.sh 를 먼저 실행하세요." >&2
    exit 1
fi
if [[ ! -f "$FW" ]]; then
    echo "오류: UEFI 펌웨어를 찾을 수 없습니다: $FW" >&2
    exit 1
fi

exec qemu-system-aarch64 \
    -M virt -accel hvf -cpu host -smp "$CPUS" -m "$MEM" \
    -drive if=pflash,format=raw,file="$FW",readonly=on \
    -drive if=virtio,format=qcow2,file="$DISK" \
    -netdev user,id=n0,hostfwd=tcp:127.0.0.1:10022-:22 \
    -device virtio-net-pci,netdev=n0 \
    -nographic
```

1. `scripts/vm-run.sh` 실행. 부팅 로그가 흐르고 `login:` 프롬프트가 나온다.


   ssh -p 10022 root@127.0.0.1 uname -mr

콘솔에서 나가려면 VM을 켜 둔 채 그냥 두면 된다 (빌드는 ssh로 진행).

- [ ] **Step 4: 검증 — 호스트 pkg 크로스 rootdir 설치 선검증**

amd64 chroot 실행이 불가능하므로, zen.conf(Task 6)가 쓸 호스트 측 크로스 설치 기법을 소형 패키지로 미리 검증한다. VM 안에서:

```sh
ABI_TARGET="FreeBSD:$(freebsd-version -u | cut -d. -f1):amd64"
mkdir -p /zen/xtest-root /zen/xtest-pkgs /zen/xtest-db
pkg -o ABI="$ABI_TARGET" -o PKG_DBDIR=/zen/xtest-db -o IGNORE_OSVERSION=yes \
    fetch -d -y -o /zen/xtest-pkgs rsync
pkg -o ABI="$ABI_TARGET" -o IGNORE_OSVERSION=yes --rootdir /zen/xtest-root \
    add <스크립트-생략-플래그> /zen/xtest-pkgs/All/*.pkg
```
